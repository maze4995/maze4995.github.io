CASE STUDY 02 / ROBOTICS / SYSTEM INTEGRATION

인식한 호실 번호를
이동할 좌표로.

자율주행 배달로봇 NextGen Deep Delivery

큰 대학 건물에서 배달 기사가 호실을 찾는 상황에 주목했습니다. 사람이 영수증의 호실 번호 부분을 카메라에 보여주면, 로봇이 사전 등록한 위치를 찾아가도록 구성했습니다.

01 / SYSTEM

입력에서 동작까지

  1. 01호실 번호 제시사람이 번호 부분을 카메라에 제시
  2. 02숫자 인식인식 결과 → 등록 호실 선택
  3. 03목표 좌표 전달사전 지도 · 코드에 등록된 좌표
  4. 04자율 이동·정지장애물 회피 · 목적지 도착

실제 영수증의 번호 인식을 확인했으며, 시연 영상에는 큰 숫자를 쓴 종이를 사용했습니다. 전체 영수증 내용의 자동 해석을 구현한 것은 아닙니다.

02 / CONTRIBUTION

내가 맡은 일

01

팀 협업 기반 마련

소프트웨어 3명, 하드웨어 구매·조립 2명으로 구성된 새 팀을 이끌었습니다. ROS·C++ 학습을 진행한 뒤 GitHub로 협업했습니다.

02

ROS 명령과 모터 연결

제조사 예제를 참고해 ROS 이동 명령을 모터 드라이버로 전달하는 브리지를 구현했습니다. 로봇 설정과 TF를 조정하고 실제 주행 속도를 맞췄습니다.

03

인식부터 목적지까지 통합

로봇을 수동 주행해 SLAM 지도를 만들고, 호실 좌표를 코드에 등록했습니다. 팀의 숫자 인식 결과를 목표 좌표 선택과 내비게이션에 연결했습니다.

03 / TROUBLESHOOTING

관찰하고, 조정한 과정

명령보다 빠른 모터 동작

ROS 명령값, 제조사 프로그램의 RPM 표시, 실제 전진 움직임을 비교하며 속도 설정을 조정했습니다. 당시 수식과 수치는 남아 있지 않아 구체적인 보정값은 제시하지 않습니다.

회전할 때 흔들리는 위치 추정

LiDAR와 T265의 간격을 넓히고 T265 기준 LiDAR 위치 오프셋을 수정한 뒤, 위치 추정의 흔들림이 줄어드는 것을 관찰했습니다. 센서 간섭은 가설이며 확정한 원인은 아닙니다.

04 / OUTCOME & REFLECTION

확인한 결과와 남은 과제

팀 결과

사전 제작한 지도에서 등록 호실을 선택하고 장애물을 회피해 도착·정지하는 흐름을 연결했습니다. 연구실 건물 1개 층의 여러 호실에서 시험했으며, 2024년 6월 4일 전자공학 창의설계경진대회 대상을 수상했습니다.

수치는 시스템 구성·평가 절차·시험 범위를 나타내며, 정확도나 성공률을 의미하지 않습니다.

구현 범위와 한계

간헐적인 위치 추정 오차가 남았습니다. 출발점 복귀, 엘리베이터, 층간 이동은 구현하지 않았습니다. DWA는 기존 알고리즘을 재사용·통합했으며, 숫자 인식 모델은 팀 작업입니다. 공개 저장소는 개발 중 스냅샷으로, 최종 시스템 전체를 재현하는 코드라고 단정할 수 없습니다.

이 경험에서 배운 점

인식 모델의 출력이 맞는 것만으로 서비스 흐름이 완성되지 않았습니다. 호실과 좌표의 대응, 센서 좌표계, 모터 명령이 이어지는 경계를 실제 움직임과 비교하며 점검하는 법을 배웠습니다.
